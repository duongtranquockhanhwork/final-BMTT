(a) SecureSign Cloud: production signing workflow

🧑‍💻 Browser (Web Crypto API)

  • Generate RSA-2048 or ECDSA P-256 key pair
  • Encrypt private key: PBKDF2-SHA256 (310k) → AES-256-GCM
  • Sign PDF bytes: RSA-PSS or ECDSA (SHA-256) → .sig
  • Sign one-time challenge (proof-of-possession)
  • Private key never leaves the device
⇄HTTPS
cookie + CSRF

⚙️ FastAPI backend

  • Security middleware: rate limit, Origin check, CSP, HSTS
  • Accounts: Argon2id, hashed session tokens, roles
  • Key registry: verify_proof_of_possession()
  • Re-verifies every signature: verify_signature()
  • Inbox access control, trust marks, audit log
  • ⛓ Evidence log: server-signed receipts (ECDSA P-256), SHA-256 hash chain
→SQL / files

🗄 Storage

  • PostgreSQL (prod) / SQLite (dev): users, sessions, public keys, documents, audit, evidence chain
  • PDF + .sig: local disk or private Vercel Blob

(b) Threats and the defense that stops each one (details: flow diagrams in Chapters 4 and 5)

✏️ Tampering

edit a signed PDF
→ SHA-256 + signature re-verified

🪪 Key substitution

claim another user's public key
→ proof-of-possession challenge

🙅 Repudiation

deny / back-date / edit the log
→ signed receipts + hash chain

🔑 Key theft

steal keys from the server
→ keys generated & encrypted in the browser
